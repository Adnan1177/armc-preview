هذه الحزمة هي التصميم المعتمد للموقع بصيغة ثابتة: HTML و CSS و JavaScript عادي، **بدون أي إطار عمل أو مكتبة أو أداة بناء**.
تُفتح كل صفحة مباشرة في المتصفح. الغرض منها أن تُنقل إلى قوالب QWeb داخل وحدة مخصصة في Odoo 19 (مثلاً `armc_website`).

## الصفحات

| الملف | الصفحة | ما يقابلها في Odoo (مقترح) |
|---|---|---|
| `index.html` | الرئيسية (النسخة الحالية) | `website.homepage` |
| `home-a.html` / `home-b.html` / `home-c.html` | ثلاثة نماذج بديلة للرئيسية — يُعتمد واحد منها | نفس القالب أعلاه |
| `menu-a.html` / `menu-b.html` / `menu-c.html` | ثلاثة نماذج للقائمة العلوية — يُعتمد واحد منها | `website.layout` (header) |
| `about.html` | من نحن | صفحة ثابتة |
| `services.html` | الخدمات (المسارات الثلاثة) | قائمة `product.template` مصنفة |
| `service-management.html` / `service-legal.html` / `service-accounting.html` | صفحة الخدمة: الاستشارات، الأسئلة الشائعة، التقييمات | صفحة منتج / فئة + نموذج التقييمات |
| `booking.html` | حجز استشارة (4 خطوات) | Controller + `sale.order` + مزود الدفع |
| `track.html` | متابعة الطلب: دخول بالجوال ← رمز التحقق ← لوحة الطلب ← الدفع | البوابة (Portal) + OTP عبر SMS |
| `contact.html` | تواصل معنا | `crm.lead` |
| `workflow.html` | مخطط سير العمل المعتمد ومراحل الطلب ورسائلها | مرجع للمطوّر فقط — ليس صفحة في الموقع |
| `pages.html` | فهرس بكل الملفات | مرجع فقط |

النماذج البديلة (a / b / c) موجودة كاملة لأن العميل لم يعتمد شكلاً نهائياً بعد. بعد الاعتماد يُحذف الباقي.

## البنية

```
*.html                 كل صفحة مستقلة وكاملة (الهيدر والفوتر داخلها)
assets/js/armc.js      سكربت واحد صغير يشغّل كل التفاعلات
assets/css/armc.css    مكان للأنماط المشتركة عند الفصل (فارغ حالياً)
```

- **الأنماط**: كل صفحة فيها وسم `<style>` في الرأس (الحركات، الأزرار، حالات التركيز)، وباقي التنسيق في سمة `style` على العناصر. عند النقل إلى Odoo يُنصح بجمع المتكرر منها في ملف SCSS داخل `web.assets_frontend`.
- **الخطوط**: ‏IBM Plex Sans Arabic للنص العربي، و IBM Plex Sans للأرقام واللاتيني (من Google Fonts).
- **الألوان الأساسية**: الأخضر الداكن `#2B4944`، الأصفر `#FFC800`، البرتقالي `#D96C00`، الخلفية الكريمية `#F7F2EB`.
- **الاتجاه**: كل الصفحات `dir="rtl"` و `lang="ar"`.
- **الجوال**: كل الصفحات متجاوبة ومختبرة على عرض 390px.

## كيف تعمل التفاعلات

كل جزء تفاعلي (خطوات الحجز، التبويبات، الأسئلة الشائعة، القائمة المنسدلة...) يحمل:

```html
<div data-armc-region="r1" data-armc-state="0"> ... </div>
```

وكل حالة بديلة لهذا الجزء محفوظة أسفل الصفحة داخل:

```html
<template id="r1-s3"> ... الشكل الكامل للجزء في الحالة 3 ... </template>
```

وجدول الانتقالات في `<script type="application/json" id="armc-flow">` بالشكل:
`{ "r1": { "0": { "2": 3 } } }` ← في الحالة 0، الزر رقم 2 داخل الجزء ينقل إلى الحالة 3.

هذا يعني أن **كل شاشة وكل حالة مرسومة جاهزة بالـ HTML** (مثلاً: الحجز خطوة 3، شاشة الدفع، رسالة النجاح، رسالة الخطأ) — يأخذها المطوّر كما هي ويحوّلها إلى قوالب QWeb، ويستبدل الانتقال الوهمي بطلب حقيقي للخادم.

الاستثناء: زر الوضع الساطع/الداكن في `home-b.html` يبدّل الصنف `light` على العنصر `.th` فقط، والألوان كلها متغيرات CSS داخل `.th` و `.th.light`.

## ما يُستبدل عند الربط

- **البيانات الظاهرة تجريبية**: الأسماء، الأرقام، رقم الطلب، الأسعار، التقييمات، أرقام التواصل. تأتي لاحقاً من Odoo.
- **الحجز** (`booking.html`): اختيار المسار ← الاستشارة ← بيانات العميل ← الدفع. عند الدفع: إنشاء `sale.order` وتأكيده بعد نجاح الدفع، فاتورة تلقائية، وإرسال التأكيد والفاتورة بالبريد وواتساب.
- **المتابعة** (`track.html`): الدخول برقم الجوال ثم رمز تحقق يصل برسالة SMS (مزود سعودي)، ثم لوحة الطلب ومراحله (مراحل CRM)، ودفع عرض السعر إن وُجد.
- **التقييمات** في صفحات الخدمات: تُجمع عبر واتساب بعد إغلاق الطلب، وتُعرض بعد موافقة الإدارة (نموذج مخصص).
- **بحث القائمة** في `menu-c.html`: الاقتراحات مرسومة كحالات، والبحث الحي يُربط بالخادم.
- **النماذج**: الحقول فيها قيم تجريبية في الحالات المحفوظة (محمد عبدالله / 551234567 / رمز 4821) فقط لعرض الشكل.

## لم يُصمَّم بعد (ضمن الخطة)

- صفحة طلبات التدريب والتوظيف (مقترح: `website_hr_recruitment`).
- لوحة "إدارة الموقع" داخل Odoo (التقييمات، الخدمات، أقسام الموقع) — تُبنى بواجهات Odoo الخلفية وليست صفحات في هذه الحزمة.
- تحديث شاشتي الحجز والمتابعة لتطابق سير العمل الجديد (الدفع أولاً) — المرجع المعتمد هو `workflow.html`.
